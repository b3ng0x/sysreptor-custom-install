Local backups (restore)

FilenameSize
Restoring a backup made on a different (or rebuilt) instance? As of this version, backups make themselves restorable anywhere: the encryption key needed to read the database is bundled directly into the archive (protected by the same BACKUP_ENCRYPTION_KEY that already protects everything else in it) and applied automatically during restore. For a backup made this way, restoring only needs two things: the backup file and its BACKUP_ENCRYPTION_KEY - nothing below this box should normally be needed.

Security trade-off, by design: this means BACKUP_ENCRYPTION_KEY alone now unlocks everything in a backup, not just the archive - protect it accordingly (it's shown on this page; anyone who can read it plus grab a copy of a backup file has everything).

The field and button below are the fallback path - still needed for backups made before this change, or if a backup's bundled key is ever missing/corrupted. Paste a recovery-key export before you click Restore to have it applied in the same action, automatically. Timing note: a database restore replaces the user table too, so this admin session ends the moment the restore runs - "Apply recovery key only" below only works after a restore if you can still reach this page some other way (a different login that still works, or an API token).
